# P-Schedule

팀 업무 관리 웹사이트 (WYD HUB 노션 개선 요청 반영). 회의·일정, 할 일, 메모, 태그를 서로 연결해서 페이지를 오가지 않고 목록·달력 화면에서 바로 보고 고칩니다. 관리자가 멤버 계정을 발급합니다.

- **오늘**: 하루 24시간 타임라인, 오늘의 할 일 (전체 / 회의 관련 / 개인 업무), 빠른 메모 (회의를 고르면 그 회의 메모로 저장)
- **대시보드**: 월간 달력 (회의·일정·할 일), 날짜를 누르면 측면 패널에 그날 회의의 핵심 안건·중요 메모·남은 할 일. 아래에 이번 달 회의를 지난 회의 / 오늘 / 내일 / 앞으로 로 묶어 표시 (전체 / 내 회의 / 참석 회의)
- **팀별 보이는 범위** (서버에서 막음): 회의·일정·할 일·메모마다 팀(조직도의 조직)이 있고, 만든 사람의 소속으로 자동 지정 (회의에 연결한 할 일·메모는 그 회의의 팀). 멤버는 자기 소속 조직과 그 아래 팀의 항목 + 다른 팀이어도 내가 관련된 것(만든 것, 참석하는 회의, 맡은 할 일, 쓴 메모, 볼 수 있는 회의에 붙은 할 일·메모)만 봄. 소속이 없으면 내 것만, 관리자는 모두. 목록·상세·검색·날짜 패널·소속 화면·회의 고르기·댓글·링크 모두 같은 규칙, 볼 수 없는 항목은 404. 팀은 만든 사람·관리자가 바꿈. 구글 캘린더는 캘린더마다 팀을 정하고, 안 정하면 모두에게 보이는 공용. 공지·조직도 보기는 모두
- **추가로 볼 수 있는 조직** (관리자): 멤버마다 소속 말고도 볼 조직을 더 지정 ('멤버 · 소속 지정 → 수정'). '아래 팀 포함'을 끄면 그 조직(부·본부 직속)만. 서버 명령: `server/admin.mjs view-add <아이디> "<조직 경로>" [only]`, `view`, `view-remove`
- **나의 대시보드**: 위 범위대로 (맨 위에 보이는 범위 안내, 관리자도 같은 규칙). 관리자용 전체 대시보드는 메뉴에서 뺐고 예전 주소(#/alldash)는 나의 대시보드로 감 (화면 코드는 남겨 둠: 다시 쓰려면 메뉴만 되살리면 됨). 예전 전체 대시보드는 모든 팀 항목, 팀으로 거르기, 팀별 이번 주 회의·남은 할 일·마감 지난 할 일 요약, 팀 미지정 묶음
- **대시보드 검색**: 전체 기간에서 안쪽 내용까지 찾음 — 회의·일정(제목, 장소, 개요, 안건, 관련 문서, 댓글, 태그·분류, 참석자), 할 일(제목, 메모, 관련 회의, 담당자, 태그·분류), 메모 본문, 구글 캘린더 일정. 띄어쓰기·영문 대소문자 무시. 결과는 날짜 순서로 묶고 오늘 위치로 이동, 어디서 찾았는지와 찾은 글자를 강조, 회의·일정 / 할 일 / 메모 거르기 (최대 300개)
- **측면 패널**: 목록·달력에서 항목을 누르면 오른쪽에 열리고, 닫지 않고 다른 항목을 골라 비교. 회의는 참석자, 개요, 안건, 준비사항, 회의 후 할 일 (담당자·상태), 메모·참고사항, 관련 문서 링크, 댓글을 그 자리에서 고침
- **회의 ↔ 할 일 연결**: 할 일에 '관련 회의'와 구분 (준비사항 / 회의 후 할 일). 메모에서 **할 일로 만들기** 하면 원래 회의에 자동 연결
- **외부 참석자**: 회의 패널의 참석자 아래에 P-Schedule 계정이 없는 분을 이름·소속·기관·연락처(선택)로 넣고 빼기. 참석자 수에 '외부 n'으로 함께 보이고 검색에도 걸림. 회의를 볼 수 있는 사람만 보고 고침
- **중요 메모**: 별표한 메모는 회의 패널 맨 위와 날짜 패널에 먼저 보임
- **분류**: 대분류 › 중분류 › 소분류 3단계. 회의·할 일·메모에 하나씩 붙이고 (회의에 연결한 할 일·메모는 회의 분류를 따름), 왼쪽 메뉴 트리에서 누르면 오늘·대시보드·할 일·회의·메모를 그 분류(와 그 아래)로 걸러 봄. 관리자가 분류 관리에서 만들고 이름·순서를 바꾸며, `기획팀 > 행사 > 개막미사` 처럼 여러 줄을 한 번에 넣을 수 있음. 분류를 지우면 붙어 있던 항목은 한 단계 위 분류로 옮겨짐
- **구글 캘린더 가져오기** (읽기 전용, 한 방향): 관리자가 '내 캘린더' 옆 톱니바퀴에서 구글 캘린더의 **비공개 주소(iCal 형식)** 를 등록하면, 서버가 20분마다 읽어서 달력·오늘 화면에 빗금 무늬로 함께 보여 줌. 캘린더 여러 개, 캘린더별 이름·색·분류, 지금 읽기. 반복·종일·시간대(한국 시각으로 변환)·예외·바뀐 회차·취소 반영, 다시 읽을 때 통째로 바꿔서 고친 것·지운 것도 반영. 구글이 보내는 HTML 설명(`<p>…</p>`, 링크·목록)은 글자만 남김 (제목의 `<A311>` 같은 방 번호는 그대로, 이미 들어온 일정도 서버 시작 때 정리). 읽기에 실패하면 이전 일정을 그대로 두고 관리 창에 오류 표시. 비공개 주소는 비밀번호처럼 다룸 (관리자만 등록, 화면에는 `calendar.google.com · …ab12` 처럼 가려서만, 로그·API 응답에 안 나옴, DB 에만 저장)
- **구글 캘린더 일정을 우리 소속으로 넣기**: 가져온 일정 패널의 '우리 소속으로 넣기'(또는 대시보드 검색 결과에서 '가져온 일정 골라 넣기'로 여러 개)로 종류(회의/일정)·팀·참석자를 골라 P-Schedule 일정으로 복사. 멤버는 내 소속과 그 아래 팀에만, 관리자는 아무 팀에. 같은 원본은 같은 팀에 한 번만 (다른 팀은 따로 가능), 이미 넣었으면 '○○에 있음 → 열기'. 넣으면 그 우리 일정을 볼 수 있는 사람에게는 원본(가져온 일정)을 달력·검색에서 숨기고, 우리 일정에 'WYD 캘린더 백업' 표시, 원본의 제목·날짜·시간·장소가 바뀌면 알림과 '원본대로 맞추기' (자동으로 덮어쓰지 않음), 원본이 지워지면 표시만
- **태그**: 팀 공용, 목록·패널에서 바로 붙이고 새로 만들기, 태그 관리 (이름·색)
- **프로젝트** (사이드바): 팀(조직)마다 프로젝트를 만들고 묶음·항목 트리로 관리. 항목마다 상태(미정·아이디어·검토·진행·확정·보류·완료)·담당·마감·메모. 목록 화면은 팀별로 묶어 완료율·상태 수를 보여 줌. 볼 수 있는 팀(소속과 아래 조직, 추가로 볼 조직, 본부장 범위)의 것만 보고 고침, 관리자는 전부, 프로젝트 삭제는 만든 사람·관리자. '목록 붙여넣기' 또는 `server/admin.mjs project-import <조직> <프로젝트> [--dry] < 목록.txt` (`1.` 묶음, `4-1.` 아래 묶음, `*` 항목, `※` 묶음 메모)
- **프로젝트 구역**: 맨 위 묶음과 프로세스에 구역 이름을 적으면 프로젝트 첫 화면이 구역 카드로 나뉘고, 카드를 눌러 그 구역의 항목·상세 프로세스로 들어감. 구역이 없는 묶음·프로세스는 '프로젝트 공통' 카드. 구역을 쓰지 않는 프로젝트는 예전처럼 바로 항목 화면.
- **항목 수량·이미지** (우선 관리자 전용·서버에서도 막음): 항목마다 수량과 이미지 한 장. 이미지는 브라우저에서 긴 변 900px·46KB 안쪽 JPEG 로 줄여 올리고, 서버는 파일 앞부분으로 JPG·PNG·WEBP 인지 확인해 DB 에 보관.
- **협력업체** (구역 안 '협력업체' 탭, 우선 관리자 전용·서버에서도 막음): 구역마다 협력업체 이름·메모(미정이면 비워 둠), 항목·묶음·상세 프로세스마다 '관련' 체크, 관련 항목·프로세스 수와 진행·다음 일정을 한눈에, '관련만' 보기.
- **상세 프로세스** (프로젝트 화면의 '상세 프로세스' 탭, 우선 관리자 전용, 서버에서도 막음): 구분 > 단계 > 세부 업무별로 진행 상세, 산출물, 시작일·예정일, 상태를 관리. WBS 화면(번호, 단계별 진척률: 완료 100·진행 50·나머지 0의 평균, 주 단위 막대)과 목록, 일정 지남 표시. 'PDF 다운로드'는 지금 조건 그대로 기준 시점이 찍힌 A4 가로 PDF를 브라우저에서 바로 만듦(이미지 페이지라 글자 선택은 안 됨). 프로젝트 항목의 담당 칸은 없앰(저장된 값은 DB에 남음). 일괄 입력: `server/admin.mjs process-import [--dry] < 프로세스.json` (원본 파일은 저장소에 넣지 말 것)
- **공지 공개 범위**: 공지마다 직원 전체 / 모든 권한(봉사자 포함) / 본부장·관리자 / 관리자만 중에서 고름. 범위 밖 권한에게는 목록·안 읽음 수·본문·댓글을 서버에서 막음. 봉사자는 공개된 공지를 읽기만 함(댓글·작성자 이름 없음). 명령: `notice-add <제목> [pin|-] [all|staff|lead|admin] < 본문`
- **입출고 수정 기록** (대장 화면 맨 아래, 접힘, 직원 이상만): 기록 추가·수정·삭제, 대장 수정을 누가 언제 무엇을 바꿨는지 최근 100건 표시. 이 기능을 넣기 전 기록의 변경 내역은 없음.
- **입출고 관리** (메뉴 '프로젝트' 아래 따로, 대장은 프로젝트 묶음에 소속, 목록도 묶음 제목 아래에 대장을 표시): 새 대장은 위치 → 이름 → 품목 → 전달 후 순서의 단계별 안내로 만들고, 상세 화면은 기본 정보 → 입고 → 출고 → 재고 확인 → 전달 후 현황 단계로 나뉨. 대장이 있는 묶음·프로젝트는 대장을 먼저 지워야 지울 수 있음. 품목 열(색상·종류)마다 입고·출고 기록, 일계·누계·합계·입고 대비 비율·창고 재고, 계약 수량·미입고, 선택으로 전달 후 현황(길이 후보별 예상 수량과 차이). 권한은 프로젝트와 같음. 일괄 입력: `server/admin.mjs stock-import [--dry] < 대장.json` (`{ project, group, ledgers: [{ name, unit, inLabel, outLabel, contract, after, options, moves: [{ type, date, handler, note, qty: { 품목: 수량 } }] }] }`, 원본 파일은 저장소에 넣지 말 것)
- **앱 설치·알림**: 사이트는 PWA(`public/manifest.webmanifest`, 서비스 워커 `public/sw.js`, 아이콘 `public/icons/`)라 휴대폰·패드·PC 에서 홈 화면에 설치해 씀. 안드로이드 앱(APK)은 사이트를 주소창 없이 여는 TWA(`android/`, 패키지 `app.vercel.pschedule`, `cd android && ./gradlew assembleRelease` 로 만들고 `public/download/pschedule.apk` 로 복사, 서명 키는 저장소 밖 `~/.pschedule-android/` 에만, 키 지문은 `public/.well-known/assetlinks.json`). 사이트를 고치면 앱도 바로 바뀌어 다시 설치할 필요 없음. 알림은 웹 푸시(`server/push.mjs`, VAPID 키는 처음 실행 때 `settings.vapid` 에 만듦, 구독 `push_subs`, 알려진 푸시 서비스 주소만 받음): 새 공지(볼 수 있는 사람), 게시판 새 글(봉사자·관리자, 비밀글은 관리자만)·내 글 댓글, 팀 봉사자 교육 등록·날짜 변경·필요 인원, 새 이슈(관리자)·이슈 처리·답(올린 사람). 계정 메뉴 '알림 · 앱 설치'에서 기기마다 켜고 끄고 시험 알림을 보냄, 그 아래 '받을 알림'에서 종류별(새 공지·게시판 새 글·내 글 댓글·교육 일정·필요 인원·새 이슈·이슈 처리·답, 계정 권한에 맞는 것만)로 켜고 끄고 전체 켜기·끄기(계정마다 `users.push_off`, 모든 기기에 적용, 시험 알림은 늘 보냄), 로그아웃하면 그 기기 구독을 지움. 기기에서 알림을 켜 두면(`ps.pushWanted`) 브라우저가 구독을 끊어도 앱을 열거나 '알림 · 앱 설치'를 열 때 다시 구독함. 서비스 워커는 알림을 받으면 띄웠는지(shown·retry·fail)를 `POST /api/push/report` 로 알려 주고(등록된 구독 주소만, 로그인 없이, 접속지마다 10분에 10번), 서버 기록에 `[push] 기기 #id …` 로 남음. 보내기 실패는 `[push] 실패 <코드> <서비스> <이유>`. 아이폰·아이패드는 홈 화면에 추가한 앱에서만 알림.

/api/projects/volunteer-dashboard`: 요약·월별 요청수량·교육물량 막대·진행률·최근 변동). 직원 프로젝트 화면(기념품팀 프로젝트)에 '봉사자 현황' 탭: 묵주·손십자가마다 수업 신청·요청수량·입고·출고·원자재·회수 요약, 최근 변동(입출고 수정 기록·요청수량 수정·원자재·회수, 봉사자 표시), 네이버폼 수업 신청과 일정 대조(이름 자동 대조, 참고용). 수업 신청은 `server/admin.mjs vol-request-import [--dry] < 신청.json` 으로 묶음째 바꿔 넣음(`vol_requests`, 연락처·담당자·질문은 넣지 않음). 직원 입출고 관리에는 '봉사자 입력' 표시·입력자·최근 입력이 나오고, 관리자는 봉사자 관리의 '입출고 입력' 탭에서 최근 100건을 봄. 일정은 달력으로 보며 봉사자가 직접 입력(자기에게만 보임, 자기 일정만 수정)하고, 관리자는 '봉사자 관리'에서 전체 또는 개인 지정 일정을 등록하고 봉사자 입력분도 봄. 교육은 관리자가 등록하고 봉사자가 이수를 직접 표시. 일정 일괄 입력: `server/admin.mjs vol-schedule-import [--dry] < 일정.json` (봉사자 전체 공개, 같은 날·같은 제목은 건너뜀, 원본 파일은 저장소에 넣지 말 것) 프로젝트는 담당자 없이 공개. 서버 입구에서 `/api/me`·비밀번호·로그아웃 말고 전부 403 이라 조직도·연락처·일정이 나가지 않음. 직원 명단·담당자·참석자·연락처·조직도 자리 연결에 나오지 않음. 봉사자로 바꾸면 소속·추가로 볼 조직·자리 연결을 지움. DB 에서는 `users.volunteer` (role 은 member)
- **본부장 권한** (멤버 화면의 권한: 봉사자 / 멤버 / 본부장 / 관리자): 맡은 조직(계정 소속 + 조직도에 연결한 자리)과 그 아래 조직의 회의·일정·할 일·메모를 봄. 보기 범위만 넓고 관리 기능·다른 사람 연락처 수정은 없음. 맨 위 조직을 맡기면 전체를 보게 되니 주의. DB 에서는 `users.director` (role 은 member)
- **연락처** (모두, 사이드바 대분류): 조직도 순서로 소속별로 묶은 표. 모든 소속과 자리가 나오고 공석·사람 없는 부서도 보임(찾을 때는 맞는 줄이 있는 소속만). 카테고리·소속 거르기, 이름·소속 찾기, 전화·메일 바로 연결. 맨 위 '내 연락처'에서 각자 입력, 관리자는 아무 줄이나 고치고 계정 없는 사람도 입력. **로그인한 사람은 모두 전체 연락처를 봄**(조직별 비공개 없음). 겸직이면 한 사람의 값이 자리마다 보임. 자리의 사람이 바뀌면 그 자리의 값은 지움. 별도 표 `contacts` 에 있고 `/api/contacts` 만 읽음: 검색·조직도 API·내보내기·로그에 나오지 않음. **DB 백업 파일에는 들어감**. 외부 조직 연락처(`external_contacts`)는 관리자가 카테고리(`contact_categories`)로 묶어 입력하고 로그인한 사람 모두 봄. 일괄 입력: `server/admin.mjs contacts-import [--dry] < 명단.tsv` (명단 파일은 저장소에 넣지 말 것, 조직도 자리의 이름으로 찾고 이미 있는 값은 유지)
- **조직도 보기** (모두, 사이드바 '조직도'): PDF 조직도처럼 위원회 → 본부 → 부 카드(가로) → 팀·분과 카드(세로, 분과 안의 팀은 점선 카드). 본부 거르기, '이름까지 / 부서·인원만', 이름·부서 찾기(그 칸으로 이동·강조), 확대·축소·화면에 맞추기. 공석은 흐리게, '나'는 파랑. 이름을 누르면 겸직 자리와 (계정이 연결돼 있으면) 그 사람의 회의·할 일, 부서를 누르면 소속 화면
- **조직도 편집** (관리자 전용): 엑셀과 같은 표 (순번 | 본부 | 부 | 팀·분과 | 직함 | 이름 | P-Schedule 계정 | 비고), 칸 바로 고치기, 부별 묶음, 본부 거르기·찾기, 줄 추가, 순번을 끌어서 순서 바꾸기. 부·팀 칸에 새 이름을 적으면 조직이 생김. 엑셀(.xlsx) 불러오기·붙여넣기 → 지금 조직도와 비교한 미리보기(추가·이동·빠짐)를 확인하고 반영 (파일은 브라우저에서 읽고 표 내용만 서버로). 확인할 것(이름 같은 자리, 공석, 계정 미연결, 빈 조직), 부서 구조 트리(끌어서 팀을 분과 아래로), 기준일, CSV 내보내기. 조직은 5단계까지 (위원회 › 본부 › 부 › 분과 › 팀), 같은 이름의 하위 조직 가능 (국제부 › 국제부)
- **조직도 자리와 계정은 따로**: 조직도의 사람(자리)은 P-Schedule 계정이 없어도 됨. 계정은 골라서 연결(이름이 같으면 연결 제안), 한 사람이 여러 자리 겸직 가능. 처음 연결하면 그 자리 조직이 멤버의 대표 소속이 됨. 인원 수는 공석 빼고, 한 조직 안에서 같은 사람은 한 번
- **소속**: 멤버마다 조직 하나 (예전 '직책' 칸 대신, 예전 직책 글자는 멤버 '메모'로 옮겨 둠). 참석자·담당자 옆과 계정 메뉴에 소속 약칭. 멤버 관리 표에서 소속 고르기·소속 미지정/관리자 거르기·여러 명 한 번에 바꾸기
- **소속 화면** (모두, 사이드바 '내 소속'·'다른 소속 보기'): 팀원·책임자, 이 팀만/하위 조직 포함, 이번 주 회의·남은 할 일·마감 지난 할 일·중요 메모 숫자, 팀원이 참석하는 회의, 팀원이 맡은 할 일 (담당자별/마감일순), 팀원이 쓴 메모 (중요 먼저). 대시보드·할 일·회의 목록의 '전체 / 우리 소속' 거르기, 참석자 고를 때 소속별로 묶고 '○○ 전체 넣기'
- **팀 색**: 달력·오늘 화면의 회의·일정은 팀(조직) 색으로. 고정: 운영총괄부 › 운영총괄팀 = 주황, 운영총괄부 › 기념품팀 = 원래 색(회의 보라·일정 파랑). 다른 팀은 남은 색(청록·분홍·빨강·연두·갈색·회청)을 조직 순서대로 자동 배정 → 팀이 늘어도 기존 팀 색은 그대로, 아래 팀은 고정 팀 색을 따름. 고정 값은 `public/app.js` 의 `TEAM_FIXED`. 사이드바 '내 캘린더' 아래 '팀 색' 안내. 팀이 없는 일정·구글 캘린더 일정은 전과 같음
- **회의실 예약 현황**(오늘): 제목 `[A602]` → 맨 앞 `A602 …` → `(A602)` → 장소 순으로 방을 찾음. `[A4소]`·`[4A소회의실]`처럼 A·4·소가 모두 있으면 'A4 소회의실', 애매한 표기는 적힌 그대로. '회의실 관리'에 `방 이름 = 다른 표기, …`로 묶고, 읽지 못한 표기는 관리자만 보고 방을 정하거나 '회의실 아님'으로 기억. 같은 방 시간 겹침·중복일 수 있음을 표시. 이름에 '부재·휴가·연차·근태'가 든 캘린더에서는 방을 찾지 않음. 설정은 settings `meeting_rooms`·`meeting_rooms_skip`
- **수정된 일정**: 구글에서 다시 읽거나 사이트에서 고쳐 제목·날짜·시각·장소가 바뀌면 '수정됨'(3일, 일정이 끝나면 그전이라도 사라짐). 오늘에서 옮겨졌거나 취소된 일정은 '오늘의 일정' 위에 한 줄. 첫 읽기·주소 바꾼 뒤 첫 읽기·한꺼번에 많이 바뀐 때·반복 전체의 시각을 옮긴 때는 표시하지 않음. 기록은 `event_edits`(30일). 열어 둔 오늘 화면은 2분마다, 다시 볼 때 새로 읽음(입력 중이거나 창이 열려 있으면 미룸)
- **원본 지워짐**: 우리 소속으로 넣은 구글 일정의 원본이 지금 없으면 해결될 때까지 달력·목록·이름으로 모아 보기·검색에 표시('오늘의 일정'과 회의실 예약 현황에는 그 일정을 그리지 않음). 캘린더를 제대로 읽을 때 한꺼번에 판단해 `events.src_state`(ok·moved·gone·lost·out)에 적음 — 읽기 실패·기간 밖·캘린더 연결 끊김·다른 캘린더로 바꾼 주소는 지워짐이 아님. 시각을 옮긴 단발과 나뉜 반복은 `src_row`로 이어 '바뀜', '원본대로 맞추기'를 누르면 다시 이음
- **부재 알림**(이름으로 모아 보기): 부재 캘린더(관리자가 켬, 안 정했으면 이름에 '부재'가 들어간 것 — `calendars.absence`)의 그날 부재를 검색어와 상관없이 모두 보여 주고, 이름마다 부재를 맨 위에. 제목은 분명할 때만 '이름 · 종류'로 나눔(`server/absence.mjs`, `node tools/absence-test.mjs`). 설명·장소는 목록에 보내지 않음
- **봉사자 계정 일괄 발급**(관리자, 봉사자 관리 › 계정 일괄 발급): 표를 붙여 넣거나 엑셀을 골라 미리 보고 한꺼번에 발급(모두 되거나 모두 안 됨, 있던 계정은 고치지 않음). 봉사자 아이디는 완성형 한글도 됨(2~20자, NFC). 임시 비밀번호는 발급 응답에서 한 번만 — DB·로그·브라우저 저장소에 남기지 않음. 세례명·연락처는 서버로 보내지 않음
- **왼쪽 메뉴 접기·폭 조절** (넓은 화면): 위쪽 화살표로 아이콘만 남기고 접기/펼치기, 오른쪽 가장자리를 끌어서 폭 조절(200~380px, 두 번 누르면 처음 폭, 키보드 좌우 화살표). 이 브라우저에 기억. 메뉴 순서는 오늘·나의 대시보드·할 일·회의·메모·조직도·공지
- **관리자 전용은 주황**: 일반 화면은 파랑, 관리자만 할 수 있는 곳은 자물쇠 + '관리자 전용' 이름표, 화면 맨 위 주황 줄, 주황 버튼. 사이드바의 관리자 메뉴(조직도, 멤버·소속 지정, 분류 관리, 구글 캘린더 연결, 백업)는 주황 상자 하나에 모으고 멤버에게는 안 보임. 서버에서도 관리자만 고칠 수 있음
- **할 일 / 회의 / 메모** 목록 화면, **공지** (관리자 작성, 댓글, 메뉴 맨 아래에 안 읽은 공지 수 표시 → 열어 보면 줄어듦, 목록에 '새 글' 표시), **멤버** (관리자: 계정 발급·임시 비밀번호 재발급·소속·권한)
- 고치기는 팀 누구나 (회의록을 함께 채우므로), 지우기는 만든 사람·관리자. 메모는 쓴 사람만 고침
- 처음 받은 비밀번호로 로그인하면 비밀번호를 바꿔야 들어갈 수 있음.
- **아이디 저장·자동 로그인** (로그인 화면 체크): 아이디 저장은 그 기기에 아이디만 기억(`ps.savedId`, 비밀번호는 저장 안 함, 로그아웃해도 남음). 자동 로그인을 켜면 토큰을 localStorage 에 두고 서버 세션 30일, 쓰는 동안 남은 기간이 15일 아래면 다시 30일로 늘림(`sessions.remember`=1). 끄면 토큰을 sessionStorage 에 둬서 창·앱을 닫으면 로그아웃되고 서버 세션도 12시간. 처음 기본값은 설치한 앱(PWA·APK)에서만 켜짐, 이후는 마지막 선택을 기억(`ps.autoLogin`). 예전 화면(값 없음)·기존 세션은 자동 로그인으로 봄

## 백업

모든 데이터(구글 캘린더 비공개 주소 포함)는 VPS 의 `/opt/pschedule/data/pschedule.db` 한 파일입니다. **백업 파일도 비밀번호처럼** 다뤄 주세요 (공유 폴더에 두지 않기).

### VPS 자동 백업 (설정 필요 없음)

API 서버가 매일 한국 시각 4시 이후 한 번 `/opt/pschedule/data/backups/pschedule-YYYY-MM-DD.db` 를 만들고, 30일 지난 것은 지웁니다. 실행 중인 DB 를 그냥 복사하지 않고 SQLite `VACUUM INTO` 로 일관된 사본을 만듭니다. VPS 의 cron 이나 다른 서비스는 건드리지 않습니다. 멤버 화면 아래 '자동 백업' 카드에서 최근 백업 확인과 '지금 백업'을 할 수 있어요.

바꾸려면 `/opt/pschedule/.env` 에 `BACKUP_KEEP_DAYS=60` (0 이면 끔), `BACKUP_HOUR=3`, `CALENDAR_SYNC_MINUTES=30` 처럼 적고 `docker compose up -d` 하세요.

```bash
ssh root@srv1809055.hstgr.cloud 'cd /opt/pschedule && docker compose exec -T api node --disable-warning=ExperimentalWarning server/admin.mjs backups'
```

### 내 Mac 으로 백업 받기

```bash
bash tools/pull-backups.sh
```

VPS 의 백업 중 아직 없는 것만 `~/PSchedule-backups` 로 받고 (`sqlite3` 로 깨지지 않았는지 검사), 이 Mac 에서는 90일 지난 것을 지웁니다. VPS 에 ssh 키로 비밀번호 없이 접속할 수 있어야 해요.

매일 자동으로 받으려면 (오전 9시 30분, 잠자기 중이었으면 깨어난 뒤):

```bash
mkdir -p ~/PSchedule-backups && cp tools/pull-backups.sh ~/PSchedule-backups/
sed "s#__HOME__#$HOME#g" tools/com.pschedule.pull-backups.plist > ~/Library/LaunchAgents/com.pschedule.pull-backups.plist
launchctl load ~/Library/LaunchAgents/com.pschedule.pull-backups.plist
```

기록은 `~/PSchedule-backups/pull.log`. 끄기: `launchctl unload ~/Library/LaunchAgents/com.pschedule.pull-backups.plist`

### 복구

1. 되돌릴 백업을 고릅니다 (VPS `/opt/pschedule/data/backups/` 또는 Mac `~/PSchedule-backups/`). 먼저 내용을 보고 싶으면 로컬에서 `DATA_DIR` 를 다른 폴더로 두고 그 파일을 `pschedule.db` 로 복사해 `npm run dev` 로 열어 볼 수 있어요.
2. VPS 에서 API 를 멈추고, 지금 DB 를 따로 보관한 뒤 백업으로 바꿉니다.

```bash
ssh root@srv1809055.hstgr.cloud
cd /opt/pschedule
docker compose stop api
mkdir -p data/before-restore && mv data/pschedule.db* data/before-restore/   # 지금 DB (WAL 파일 포함) 보관
cp data/backups/pschedule-2026-11-01.db data/pschedule.db                    # Mac 에서 올릴 땐: scp ~/PSchedule-backups/pschedule-2026-11-01.db root@srv1809055.hstgr.cloud:/opt/pschedule/data/pschedule.db
chown 1000:1000 data/pschedule.db
docker compose start api
docker compose logs --tail 5 api
```

3. 사이트에 로그인해 확인합니다. 로그인 세션도 백업 시점으로 돌아가서 다시 로그인해야 할 수 있어요. 문제가 있으면 `data/before-restore/` 의 파일로 같은 방법으로 되돌리면 됩니다.

## 보안 메모
- 로그인 실패 제한(10분): 아이디+접속 IP 10회, 아이디 전체 30회, 프록시가 확인한 실제 접속지 100회. 접속 IP 헤더는 꾸밀 수 있어 보조로만 씀. 없는 아이디도 같은 시간이 걸림.
- 화면 보안 정책(CSP)·다른 사이트 안에 넣기 금지는 `vercel.json` 과 서버 로컬 개발 응답(`CSP`)에 같은 값으로 둠. 외부 글꼴은 cdn.jsdelivr.net 만 허용.
- 서버 프로그램이 만드는 DB·백업 파일은 소유자만 읽고 쓰게(umask 077) 만들고, VPS 의 `data` 폴더도 소유자 전용 권한.
- 조직도 CSV 내보내기는 =, +, -, @ 로 시작하는 값 앞에 ' 를 붙여 엑셀 수식 실행을 막음.

## 관리자 메뉴
'관리자 전용' 상자를 네 파트로 나눔: 수정중 카테고리(아직 관리자에게만 공개한 기능이 있는 프로젝트 바로가기) / 직원 관리(멤버·소속 지정, 조직도 편집) / 봉사자 관리(봉사자 일정, 기본 교육, 입출고 입력) / 공통 관리(분류 관리, 구글 캘린더 연결, 백업).

## 게시판 (봉사자·관리자)
봉사자 메뉴 '게시판'과 관리자 메뉴 '게시판'(`#/board`). 분류는 요청·건의·자유, 댓글 가능. 직원(관리자가 아닌)은 못 씀(403). 비밀글은 쓴 사람 본인과 관리자 모두만 내용을 보고, 다른 사람에게는 '비밀글입니다'로만 보이며 댓글도 못 닮. 고치기·지우기는 쓴 사람과 관리자(`board_posts`, `board_comments`). 처음부터 봉사자에게 열었음(사용자 결정).

## 검수 관리 (관리자 전용으로 먼저)
'봉사자 관리 › 검수 관리' 탭. 검수할 때마다 한 줄: 묶음(묵주·손십자가), 단계(1차 수도회 자체 · 2차 외부 봉사자 · 3차 부서 봉사자), 검수일, 대상, 검수 수량, 샘플링 여부·샘플 수, 불량 유형별 수량(색상 차이·굵기·길이·매듭·파손·오염·기타), 메모, 사진 4장(`inspections`, `inspection_photos`). 기간·단계·묶음으로 거르고 단계별 불량률을 보며, 거른 기록을 업체 클레임 근거로 CSV 내려받기·인쇄(사진 포함). 샘플링이면 불량률은 샘플 수 기준.

## 오늘: 이름으로 모아 보기
